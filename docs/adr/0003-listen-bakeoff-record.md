# 横评记录只留犹豫、说完、延迟和用量

离线横评要能看出模型听得稳不稳，但不能把模型转写、语气或情绪写成考生的分数。因此一个录音文件对应一条横评记录，里面只有两次说法判断、两次延迟和两次用量。说法判断只含犹豫和说完，而且必须是明确的是或否；含糊、缺项、超时和接口错误都是未判断。两次相同为稳定，有一项不同为不稳定，至少一次未判断为未完成。

## 考虑过的做法

- 留下模型转写：会被当成权威转写。权威转写仍是现有语音转写。
- 把两次判断合成一个：不稳定就看不见了。
- 满三十条就写「可以接入直播」：接入仍是以后的决定。
- 把语气或情绪排进后续计划：和「不做情绪推断」冲突。以后若增加听法信息，另立一项，不能用这两个词。

## 后果

录音和横评记录都在仓库外，路径只在本机配置里。文件之间串行，同一文件的两次也串行；再跑同一个文件就换掉原来的两次。第二次没跑成时保留第一次，整条为未完成。单次等待 120 秒，超时记为未判断，延迟记满这次等待。打不开或不是音频时不调用模型，延迟留空。不满三十个文件标为未达门槛。满了以后的横评结论只汇总条数、稳定、不稳定、未完成、延迟和用量。请求只发音频和问题，温度取 0，只收回文字。结构化面试不读这些记录。
